진척을 꾸미지 않는
세 가지 제약

좋은 상태 보고는 더 많은 문장이 아니라 더 선명한 경계를 만듭니다.

01

목표는 북극성

오늘 할 일을 목표로 바꾸지 않습니다. 이전 좌표의 목표 문구와 게이지를 세션 사이에 계승합니다.

02

다음은 행동 하나

목표에 가장 가까운 관측 가능한 행동 하나만 둡니다. 사용자가 “다음”이라고 하면 실제로 그 게이트까지 갑니다.

03

검증은 복사 가능

“확인해 보세요” 대신 정확한 입력이나 클릭 경로와 사용자가 볼 기대 결과를 한 세트로 남깁니다.

설치했다고
활성화하지 않습니다.

사용자 지침은 제품 데이터입니다. 명시 요청, 대상 판정, diff, 백업, 마커 범위 검증을 모두 통과해야 바뀝니다.

01 / INSTALL

플러그인만 설치

스킬과 스크립트가 발견됩니다. 이 단계에서는 어떤 AGENTS 파일도 수정하지 않습니다.

02 / DRY-RUN

대상과 이유 표시

CODEX_HOME과 override 우선순위를 적용하고 프로젝트 지침은 경고만 합니다.

03 / DIFF

변경을 먼저 확인

관리 마커 안에서 무엇이 삽입·갱신·제거되는지 unified diff로 보여줍니다.

04 / APPLY

백업 뒤 원자적 반영

명시 승인 뒤에만 씁니다. 재실행해도 블록은 하나이고 제거 시 원문 바이트가 돌아옵니다.

활성 파일 판정

비어 있지 않은 AGENTS.override.md → AGENTS.md 순서. 선택 근거를 매번 출력합니다.

관리 범위

<!-- m1kskills:work-coordinates:start -->와 end 사이만 갱신합니다. 중복·깨진 마커는 안전 중단합니다.
